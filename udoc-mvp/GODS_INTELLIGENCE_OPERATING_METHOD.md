## 1. Principle (non-negotiable)

| Layer | Role | Controller? |
|-------|------|-------------|
| **A — Client models** | Usage / optional assist | No |
| **B — UDOC deterministic** | Policy, EVA, fail-closed, audit | **Yes (primacy)** |
| **C — GODS / GIS corpus** | Structured knowledge substrate | Feeds B; does not override B |

Generic LLM fluency is **not** the controller.  
Structured corpus + rules + evaluation + audit **are**.

The book's durable contribution is **discipline**, not plugins or token limits:

> structured input → constrained task → iterate → analyze → verify → controlled output

That maps directly onto UDOC's existing fail-closed, evidence, and dual-path intelligence design.

## 2. What we incorporate (and what we reject)

### Incorporate
- Sectioned document production (not one-shot 250-page generation)
- Reusable role prompts as **system components** (Research, Architecture, Governance, Investment, Red-Team, Document)
- Knowledge-base posture: organizational data → grounded answers (already Client KB + GODS intel dual-path)
- Training/onboarding material generation patterns → GBS / SETHS curriculum engine **design**
- Research progression: question → method → evidence → error sources → ethics → report
- Audience transforms from one master truth (investor / government / technical / public)
- Mandatory verification / red-team stage before high-stakes claims

### Reject / do not adopt as architecture
- Treating ChatGPT (or any LLM) as system of record
- Product-specific 2023 instructions (GPT-3.5/4 plugins, Bing, 4k context) as requirements
- Unverified fluent output as legal, patent, investment, or policy truth
- Prompt collections without corpus, policy, or audit

## 4. Intelligence pipeline (deterministic model)

```
Source corpus (Canon · policy · Neon extracts · approved uploads)
    → Ingest / classify (category · division · tags)
    → Structured records (not raw chat memory)
    → Policy layer (active packs · runtime-matrix)
    → Organizational rules (UDOC fail-closed)
```

## 5. G.O.D.S Prompt Operating System (agent roles)

Reusable components — **inputs are verified corpus slices**, not free-form invent:

| Agent | Input | Task | Output |
|-------|--------|------|--------|
| **Research** | Source material + question | Investigate | Findings · evidence · assumptions · contradictions · open questions |
| **Architecture** | Requirements + constraints (Neon 500MB, Render free, honesty) | Design | Components · dependencies · risks · sequence |
| **Governance** | Policy + constitution + regs | Evaluate | Compliant / non-compliant / ambiguous / needs legal |
| **Investment** | Business model + numbers (honesty-bounded) | Case | TAM/SAM/SOM · risks · capital · scenarios (no fabricated AUM) |
| **Red-Team** | Any major proposal | Attack | Weak assumptions · contradictions · unsupported claims · legal/tech holes |
| **Document** | Verified sources only | Produce | Versioned doc · references · cross-links · terminology check |
| **Curriculum (GBS/SETHS)** | Role profile + pathway stage | Train design | Assessment · pathway · scenarios · KPIs · placement criteria |
| **Verify** | Draft + sources | Compulsory check | Pass / fail / fix list before release |

**Compulsory order for high-stakes material:**  
Research → Document draft → Red-Team → Governance → Verify → Release.
