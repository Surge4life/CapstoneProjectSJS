# Chapter 05 — Mobile Builds (Capacitor)

## Overview

Each division app has a Capacitor-based mobile build. Capacitor wraps the existing web PWA in a native shell, providing access to native device APIs and enabling distribution as a `.apk` (Android) or `.ipa` (iOS).

---

## Capacitor Approach

G.O.D.S uses **Capacitor** (not React Native). This means:
- The web app runs in a WebView inside the native shell
- All application logic is shared between web and mobile — no separate mobile codebase
- Native APIs (camera, push notifications, file picker) are accessed via Capacitor plugins
- The mobile build is the web app, packaged for native distribution

---

## Directory Structure

```
{division}-mobile/
├── android/          Android Studio project (auto-generated by Capacitor)
│   ├── app/
│   │   ├── src/
│   │   └── build.gradle
│   └── capacitor.settings.gradle
├── ios/              Xcode project (auto-generated by Capacitor)
├── capacitor.config.ts  Capacitor configuration
└── package.json
```

The `android/` and `ios/` directories are generated by Capacitor. Do not edit them directly — they are regenerated when `npx cap sync` is run.

---

## The Build Process

```bash
# 1. Build the web app
cd seths-app
npm run build

# 2. Sync the build to the native projects
cd ../seths-mobile
npx cap sync

# 3a. Open in Android Studio (for APK)
npx cap open android
# Then: Build → Generate Signed APK

# 3b. Open in Xcode (for iOS IPA, macOS only)
npx cap open ios
```

**Important constraint:** APK/IPA builds require a machine with Android Studio + JDK 17 (Android) or Xcode (iOS). This cannot be done in a cloud sandbox environment due to SDK licensing restrictions and memory requirements.

## Capacitor Configuration

```typescript
// capacitor.config.ts (example for seths-mobile)
import { CapacitorConfig } from '@capacitor/cli';

const config: CapacitorConfig = {
  appId: 'com.gods.seths',
  appName: 'SETHS',
  webDir: '../seths-app/dist',    // Points to the built web app
  server: {
    androidScheme: 'https',
  },
  plugins: {
    PushNotifications: {
      presentationOptions: ['badge', 'sound', 'alert'],
    },
    LocalNotifications: {
      smallIcon: 'ic_stat_icon_config_sample',
    },
  },
};

export default config;
```

## PWA vs Native App

The division apps are installable as PWAs today — no APK required. The Capacitor build adds:
- Google Play / App Store distribution
- Push notification delivery (more reliable than web push)
- Native camera and file system access
- Better offline experience (native storage vs service worker cache)
- Home screen presence without "Add to Home Screen" prompt

For most use cases, the PWA is sufficient. The Capacitor build is for clients who require Play Store distribution or native device features.

## Code Signing

APK signing requires a keystore file. The keystore:
- Must be generated once per app ID
- Must be stored securely (not in the repository)
- Must be backed up — losing the keystore means losing the ability to update the app on the Play Store
- Password managed via secrets management (not hardcoded)

```bash
# Generate keystore (one-time)
keytool -genkey -v -keystore gods-seths.keystore \
  -alias gods-seths -keyalg RSA -keysize 2048 -validity 10000
```
