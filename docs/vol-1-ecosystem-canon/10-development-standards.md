# Chapter 10 — Development Standards

## Standards Every G.O.D.S Developer Must Follow

These standards ensure that every contribution to the G.O.D.S codebase meets the same quality bar, regardless of who wrote it or when.

---

## Backend Standards (Python / FastAPI)

### Language Version
Python 3.12+. No code is merged that uses deprecated APIs or syntax from earlier versions.

### Framework
FastAPI with Pydantic v2 for request/response validation. No raw dict responses — every endpoint returns a Pydantic model.

### Code Style
- `ruff` for linting and formatting (replaces flake8 + black + isort)
- Maximum line length: 100 characters
- Type hints required on all function signatures — no untyped function is merged
- Docstrings required on all public functions, classes, and modules

### Router Conventions
```python
# Every router follows this pattern:
router = APIRouter(
    prefix="/resource-name",
    tags=["resource-name"],
    dependencies=[Depends(verify_token)]  # Always authenticated
)

@router.get("/{resource_id}", response_model=ResourceResponse)
async def get_resource(
    resource_id: UUID,
    db: Session = Depends(get_db),
    current_user: User = Depends(get_current_user)
) -> ResourceResponse:
    """
    Retrieve a resource by ID.
    
    Requires: authenticated user with 'resource:read' permission.
    Returns: ResourceResponse with full resource details.
    Raises: 404 if not found, 403 if insufficient permissions.
    """
    ...
```

### Database Access
- SQLAlchemy ORM for all database operations
- No raw SQL strings in application code (use ORM or parameterised queries only)
- Every database operation happens within a managed session (via `Depends(get_db)`)
- Transactions are explicit — no auto-commit

### Error Handling
```python
# Correct: explicit, structured error
raise HTTPException(
    status_code=404,
    detail={
        "code": "RESOURCE_NOT_FOUND",
        "message": f"Resource {resource_id} not found",
        "resource_type": "ResourceName"
    }
)

# Incorrect: generic error
raise HTTPException(status_code=404, detail="Not found")
```

### Logging
```python
import logging
logger = logging.getLogger(__name__)

# Structured logging — always include context
logger.info("Decision created", extra={
    "decision_id": str(decision.id),
    "model_id": str(request.model_id),
    "outcome": decision.outcome,
    "operator_id": str(current_user.id)
})
```

## Frontend Standards (TypeScript / React / Vite)

### Language
TypeScript strict mode. No `any` types without explicit justification in a comment.

### Component Standards
- Functional components only — no class components
- One component per file
- Props interface defined above the component
- No inline styles — use CSS modules or Tailwind classes

```tsx
// Correct pattern
interface DecisionCardProps {
  decisionId: string;
  outcome: 'APPROVE' | 'REVIEW' | 'ESCALATE' | 'BLOCK';
  timestamp: Date;
  onReview?: () => void;
}

export function DecisionCard({ decisionId, outcome, timestamp, onReview }: DecisionCardProps) {
  // ...
}
```

### State Management
- `useState` for local component state
- `useReducer` for complex local state
- Context API for shared UI state (theme, user session)
- No global state management library unless justified and documented

### API Calls
All API calls go through the `api.ts` module at the app level. No `fetch` or `axios` calls directly in components.

```typescript
// In api.ts
export async function getDecision(id: string): Promise<Decision> {
  const response = await apiClient.get(`/decisions/${id}`);
  return DecisionSchema.parse(response.data);
}

// In component — call the api module function, never fetch directly
const decision = await getDecision(id);
```

### PWA Requirements
Every frontend app is a PWA. This means:
- Service worker registered and functional
- `manifest.json` complete with icons at all required sizes
- App works offline for core read operations (governance dashboard, decision history)
- Install prompt handled gracefully

## Testing Standards

### Coverage Requirements
| Layer | Required Coverage |
|-------|-----------------|
| Governance engines | 90%+ |
| Platform-core routers | 80%+ |
| Platform-core services | 85%+ |
| Frontend components | 70%+ |
| End-to-end (smoke tests) | 31/31 paths |

### Test Naming
```python
def test_governance_blocks_fairness_violation():
    """Verify that a request flagged for protected characteristic reference receives BLOCK."""
    ...

def test_oversight_case_created_on_block():
    """Verify that a BLOCK decision automatically creates an OversightCase."""
    ...
```

### Test Data
- No real PII in test data
- Synthetic data generated by `factories` module
- Database state reset between tests
- No test that depends on another test's side effects

## Documentation Standards

Every new module, service, and router must include:

1. A docstring explaining the module's purpose, scope, and key constraints
2. An entry in the appropriate Volume of this Engineering Canon (Volume II for services, Volume VIII for API endpoints)
3. Update to the relevant repository blueprint entry (Volume III)

Documentation is not optional. A PR that adds a new service without documentation is not merged.
